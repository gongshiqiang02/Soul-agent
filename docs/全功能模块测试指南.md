## 1. 测试前准备

### 1.1 环境要求

| 项目 | 要求 |
|------|------|
| Python | 3.11+ |
| 包管理 | 推荐 `uv`，也可使用 `pip` |
| 终端 | Windows PowerShell / CMD / Bash 均可 |
| 可选依赖 | 有效的 OpenAI 兼容 API Key 或本地 Ollama 服务 |

### 1.2 安装依赖

```powershell
uv venv
.venv\Scripts\activate
uv pip install -e ".[dev]"
```

**预期效果：**

- 创建 `.venv` 虚拟环境。
- 安装项目本体与开发依赖。
- `soul-agent` 命令可在当前虚拟环境中使用。

### 1.3 基础验证

```powershell
python --version
soul-agent config
pytest tests/ -v
```

**预期效果：**

- `python --version` 显示 Python 3.11 或更高版本。
- `soul-agent config` 输出当前模型、Provider、Base URL、记忆系统状态、最大迭代次数、已启用工具。
- `pytest tests/ -v` 通过当前测试集；按项目说明应覆盖 Agent、Memory、Tools 三类核心测试。

## 2. 总体架构与测试覆盖范围

### 2.1 分层架构设计

```text
用户终端
  │
  ▼
CLI / App 层
  ├─ main.py：命令入口
  ├─ cli.py：Click 命令定义
  └─ app.py：组件初始化、依赖组装、交互循环
  │
  ▼
UI 层
  ├─ Renderer：Rich Markdown、面板、表格渲染
  ├─ InputHandler：prompt_toolkit 输入处理
  └─ themes：终端主题
  │
  ▼
Core 层
  ├─ Agent：ReAct 主循环
  ├─ Conversation：消息历史与系统提示词拼接
  ├─ ContextManager：token 估算与上下文裁剪
  └─ TaskPlanner：复杂任务规划
  │
  ├──────────────┬──────────────┬──────────────┐
  ▼              ▼              ▼              ▼
Memory 层       Tools 层       LLM 层         Config / Utils
短期记忆        工具注册        LLMClient      Pydantic 配置
长期记忆        工具执行        OpenAIProvider 日志
混合检索        内置工具        LocalProvider  异常
摘要生成
```

### 2.2 测试覆盖矩阵

| 模块 | 主要源码 | 自动化测试 | 手动/端到端测试 |
|------|----------|------------|-----------------|
| 应用入口 / CLI | `main.py`、`cli.py`、`app.py` | 间接覆盖 | `soul-agent config`、`memory`、`ask`、`chat` |
| Config | `config/settings.py`、`defaults.py` | 间接覆盖 | 配置输出、环境变量覆盖 |
| Core | `core/agent.py`、`conversation.py`、`context.py`、`planner.py` | `tests/test_agent.py` | 单次问答、工具调用链路 |

| Memory | `memory/` | `tests/test_memory.py` | 存储、列表、检索、跨会话验证 |

## 5. Core 核心模块测试

### 5.1 模块架构设计

```text
Agent.run(user_input)
  ├─ MemoryManager.retrieve(user_input)
  ├─ SYSTEM_PROMPT 注入工具描述
  ├─ Conversation.build_messages()
  ├─ ReAct 循环，最多 max_iterations 轮
  │   ├─ LLMClient.chat(messages, tools)
  │   ├─ 若返回 tool_calls：ToolExecutor.execute_batch()
  │   └─ 若无 tool_calls：得到最终回复
  ├─ MemoryManager.process_turn(user_input, final_content)
  └─ Conversation.add_turn(user_input, final_content)
```

### 5.2 Conversation 消息管理测试

```powershell
pytest tests/test_agent.py::TestConversation -v
```

**预期效果：**

- `build_messages` 能生成 system + user 消息。
- `add_turn` 能正确追加 user / assistant。
- 历史消息能参与构建。
- 记忆内容能注入 system prompt。
- 超过 20 轮对话时会自动裁剪。

### 5.3 ContextManager 上下文测试

```powershell
pytest tests/test_agent.py::TestContextManager -v
```

**预期效果：**

- 英文与中文文本 token 估算均返回正数。
- 消息裁剪后保留 system 消息与最后一条 user 消息。

### 5.4 Agent ReAct 循环测试

```powershell
pytest tests/test_agent.py::TestAgent -v
```

**预期效果：**

- 普通对话：LLM 被调用一次，返回文本回复。
- 工具调用：第一次 LLM 返回 tool call，执行工具后再次调用 LLM，最终返回文本。
- `reset()` 能清空对话历史。

### 5.5 最大迭代次数手动验证

可通过配置文件将 `agent.max_iterations` 临时设为较小值，例如 `1`，再让模型执行需要多步工具调用的任务。

**预期效果：**

- Agent 最多执行配置指定轮数。
- 达到上限时不会无限循环。

## 6. LLM 适配模块测试

### 6.1 模块架构设计

```text
LLMClient
  ├─ 读取 LLMConfig.provider
  ├─ provider = openai → OpenAIProvider
  ├─ provider = local  → LocalProvider
  └─ chat(messages, tools, stream)
      └─ provider.chat(...)

OpenAIProvider
  ├─ AsyncOpenAI 客户端
  ├─ 普通对话
  ├─ 流式对话
  └─ OpenAI function calling / tool_calls 解析

LocalProvider
  └─ 继承 OpenAIProvider，默认 base_url 指向本地 Ollama 兼容接口
```

### 6.2 Provider 选择测试

```powershell
python -c "from soul_agent.config.settings import LLMConfig; from soul_agent.llm.client import LLMClient; print(type(LLMClient(LLMConfig(provider='openai')).provider).__name__); print(type(LLMClient(LLMConfig(provider='local')).provider).__name__)"
```

**预期效果：**

- 第一行输出 `OpenAIProvider`。
- 第二行输出 `LocalProvider`。

### 6.3 OpenAI 兼容 API 调用测试

先设置环境变量：

```powershell
$env:OPENAI_API_KEY = "你的 API Key"
$env:SOUL_AGENT_MODEL = "你的模型名"
# 如使用兼容 API，再设置：
# $env:OPENAI_BASE_URL = "https://api.example.com/v1"
```

执行：

```powershell
soul-agent ask "请回复：LLM 模块测试成功"
```

**预期效果：**

- 输出助手回复。
- 回复语义上包含或确认 `LLM 模块测试成功`。
- 若 API Key、模型名或 Base URL 不正确，应输出 `处理失败`，并在错误信息中体现调用失败原因。

### 6.4 本地 Ollama 调用测试

前置条件：本机已启动 Ollama，并已拉取配置中的模型。

```powershell
ollama list
soul-agent ask "请回复：本地模型测试成功"
```

**预期效果：**

- `ollama list` 能看到本地模型。
- 当配置 `llm.provider: local` 且模型存在时，`soul-agent ask` 能得到本地模型回复。

## 13. 常见问题与判断标准

### 13.1 没有 API Key 时哪些测试应该通过？

应通过：

- `soul-agent config`
- `soul-agent memory`
- `pytest tests/ -v`
- `ruff check .`
- 大部分直接调用配置、工具、记忆存储的测试

可能失败或输出错误提示：

- `soul-agent ask ...`
- 需要真实 LLM 的端到端对话、记忆提取、工具自主调用测试

### 13.2 ChromaDB 不可用时如何判断是否正常？

记忆系统设计允许降级为关键词搜索。判断标准：

- `MemoryManager.initialize()` 不应导致整个应用不可用。
- `retrieve("关键词")` 仍应能通过关键词方式返回相关记忆。
- 日志中可以出现降级或警告，但用户侧功能不应完全中断。

### 13.3 Web 请求测试失败是否一定是代码问题？

不一定。可能原因包括：

- 本机网络不可用。
- 目标站点不可访问。
- 代理或证书问题。
- 防火墙限制。

判断标准是：失败时工具返回结构化失败结果，CLI 能展示错误，而不是未捕获异常崩溃。

### 13.4 Shell 工具测试需要注意什么？

- 只执行安全、可逆、无副作用的命令，例如 `python --version`。
- 危险命令应被黑名单拦截。
- 长时间命令应受超时限制。
