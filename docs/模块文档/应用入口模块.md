# 应用入口模块

本文档描述 Soul-agent 的应用入口与组装层，覆盖以下文件：

```
soul_agent/
├── main.py       # 控制台脚本入口
├── cli.py        # Click 命令定义
└── app.py        # 应用运行逻辑与依赖组装
```

严格来说，这三份文件不属于某个子目录模块，但它们连接 CLI、UI、Core、Memory、Tools、LLM、Config，是整个软件从命令行启动到 Agent 执行的关键路径。

---

## 1. 职责划分

| 文件 | 职责 |
|------|------|
| `main.py` | 暴露 `main()` 函数，作为 `pyproject.toml` 中 `soul-agent` 命令的入口 |
| `cli.py` | 使用 Click 定义命令行命令：`chat`、`ask`、`memory`、`config` |
| `app.py` | 创建 Agent 及依赖对象，运行交互循环、单次问答、记忆查看 |

整体关系：

```
终端命令 soul-agent
        │
        ▼
    main.py:main()
        │
        ▼
      cli.py:cli
        │
        ├─ chat   ──→ app.run_chat()
        ├─ ask    ──→ app.run_ask(message)
        ├─ memory ──→ app.run_memory()
        └─ config ──→ load_config() 后输出配置
```

---

## 2. main.py

`main.py` 非常薄，只做一件事：调用 CLI。

```python
from soul_agent.cli import cli


def main():
    cli()


if __name__ == "__main__":
    main()
```

它对应 `pyproject.toml` 中的脚本配置：

```toml
[project.scripts]
soul-agent = "soul_agent.main:main"
```

因此用户执行：

```bash
soul-agent
```

时，实际调用链是：

```
soul-agent 命令 → soul_agent.main:main → cli()
```

## 3. cli.py

`cli.py` 使用 Click 定义命令行接口。

### 3.1 根命令

```python
@click.group(invoke_without_command=True)
@click.pass_context
def cli(ctx):
    """Soul-agent: 更懂你的通用Agent"""
    if ctx.invoked_subcommand is None:
        ctx.invoke(chat)
```

关键设计：

- `invoke_without_command=True` 允许不带子命令直接运行。
- 如果用户只输入 `soul-agent`，默认进入 `chat` 交互模式。

### 3.2 chat 命令

```python
@cli.command()
def chat():
    from soul_agent.app import run_chat
    asyncio.run(run_chat())
```

作用：启动交互式对话主循环。

调用链：

```
soul-agent chat
  ↓
cli.chat()
  ↓
asyncio.run(run_chat())
  ↓
app.run_chat()
```

### 3.3 ask 命令

```python
@cli.command()
@click.argument("message")
def ask(message: str):
    from soul_agent.app import run_ask
    asyncio.run(run_ask(message))
```

作用：单次提问，不进入交互循环。

示例：

```bash
soul-agent ask "解释一下 ReAct 模式"
```

### 3.4 memory 命令

```python
@cli.command()
def memory():
    from soul_agent.app import run_memory
    asyncio.run(run_memory())
```

作用：读取并展示长期记忆列表。

### 3.5 config 命令

```python
@cli.command()
def config():
    from soul_agent.config.settings import load_config
    cfg = load_config()
    console.print(...)
```

该命令不创建 Agent，只加载配置并输出核心配置项：

- 模型名称
- Provider
- Base URL
- 记忆系统是否启用
- 最大迭代次数
- 任务规划状态与复杂度阈值
- 已启用工具列表

## 4. app.py

`app.py` 是应用的“胶水层”，负责创建对象、连接依赖、驱动交互流程。

### 4.1 create_agent()

```python
async def create_agent(config=None):
    if config is None:
        config = load_config()

    llm_client = LLMClient(config.llm)

    memory_manager = None
    if config.memory.enabled:
        memory_manager = MemoryManager(config.memory, llm_client)
        await memory_manager.initialize()

    tool_registry = ToolRegistry()
    register_builtin_tools(tool_registry, config)
    tool_executor = ToolExecutor(tool_registry)

    agent = Agent(config, llm_client, memory_manager, tool_registry, tool_executor)

    # 预创建首个会话（含持久化回调），让 /history 可立即看到
    if memory_manager:
        await memory_manager.create_conversation_with_id(
            agent.conversation.conversation_id
        )
        agent._conversation_started = True
        agent.conversation.set_persist_callback(agent._persist_message)

    return agent
```

依赖创建顺序：

```
load_config()
   │
   ├─ LLMClient(config.llm)
   │
   ├─ MemoryManager(config.memory, llm_client)
   │      └─ initialize(): 创建 SQLite 表
   │
   ├─ ToolRegistry()
   │      └─ register_builtin_tools(): 按配置注册内置工具
   │
   ├─ ToolExecutor(tool_registry)
   │
   └─ Agent(config, llm_client, memory_manager, tool_registry, tool_executor)
```

该函数体现了项目的依赖注入设计：各模块对象由 app 层组装，Core 层不负责创建具体依赖。

### 4.2 run_chat()

交互式对话主循环。

流程：

```
加载配置
  │
  ├─ 创建 Renderer
  ├─ 创建 InputHandler
  ├─ 渲染欢迎界面
  ├─ create_agent()
  ├─ 设置 Agent 四个回调（工具调用、工具结果、计划进度、流式输出）
  │
  ▼
while True:
  清除上一轮计划面板 (clear_plan_live)
  读取用户输入
  ├─ 如果是 / 命令 → 内部处理（/quit, /exit, /help, /clear, /memory, /history, /name, /config）
  └─ 否则 → Agent.run(user_input) → 收起计划面板 → 渲染回复
```

### 4.3 交互命令处理

`run_chat()` 直接处理以下命令：

| 命令 | 行为 |
|------|------|
| `/quit` `/exit` | 输出再见并退出循环 |
| `/help` | 调用 `renderer.render_help()` |
| `/clear` | 调用 `agent.reset()` 创建新会话（旧会话保留） |
| `/memory` | 调用 `agent.memory.list_all()` 并用表格展示 |
| `/history` | 调用 `agent.memory.list_conversations()` 展示历史会话列表 |
| `/name <标题>` | 调用 `agent.rename_conversation()` 为当前会话命名 |
| `/config` | 输出模型和 provider 信息 |
| 其他 `/xxx` | 输出未知命令错误 |

这类命令不进入 LLM，不会触发 Agent 推理。

### 4.4 普通对话处理

```python
renderer.clear_plan_live()
renderer.render_user_input(user_input)
try:
    response = await agent.run(user_input)
    renderer.clear_plan_live()  # 收起 Live 面板后显示回复
    renderer.render_assistant(response)
except Exception as e:
    renderer.render_error(f"处理失败: {e}")
    logger.error(f"Agent运行错误: {e}", exc_info=True)
```

普通输入进入完整 Agent 流程：记忆检索、消息构建、LLM 调用、工具执行、记忆更新。

### 4.5 run_ask()

单次问答模式：

```python
async def run_ask(message: str):
    config = load_config()
    renderer = Renderer(config.ui.theme)
    agent = await create_agent(config)
    response = await agent.run(message)
    renderer.render_assistant(response)
```

特点：

- 不创建 `InputHandler`。
- 不进入 while 循环。
- 处理完一次输入后退出。
- 仍然会初始化记忆和工具系统。

### 4.6 run_memory()

记忆查看模式：

```python
async def run_memory():
    config = load_config()
    renderer = Renderer(config.ui.theme)

    if not config.memory.enabled:
        renderer.render_info("记忆系统未启用")
        return

    memory_manager = MemoryManager(config.memory)
    await memory_manager.initialize()
    memories = await memory_manager.list_all()
    renderer.render_memory_list(memories)
```

特点：

- 不创建 LLMClient。
- 不创建 Agent。
- 只初始化 MemoryManager，用于读取 SQLite 记忆。

## 6. 设计特点

### 6.1 CLI 与业务逻辑分离

`cli.py` 只负责命令定义，不直接写业务逻辑。真正的运行流程都放在 `app.py`。

### 6.2 同步 CLI 包装异步应用

Click 命令是同步函数，而应用内部是异步逻辑，因此使用：

```python
asyncio.run(run_chat())
```

这样既保持 CLI 简洁，又支持异步 LLM、数据库和工具执行。

### 6.3 统一对象组装点

`create_agent()` 是唯一组装 Agent 依赖的位置，方便未来：

- 替换 LLMProvider
- 替换 MemoryManager
- 增加插件工具
- 增加测试注入

### 6.4 命令分流明确

交互命令 `/xxx` 在 `app.py` 处理，普通自然语言输入才交给 Agent。这样可以避免 `/memory`、`/clear` 这类控制命令被 LLM 误解。

---

## 7. 当前限制与改进方向

1. **config 命令输出较少**：目前只显示核心字段，未来可输出完整配置树。
2. **run_memory 不接入向量库**：当前只查看 SQLite 中的结构化记忆。
3. **交互命令硬编码**：~~未来可抽象为命令注册表。~~ 已新增 `/history` 和 `/name`，回调也已扩展到四个（含 `on_tool_result`、`on_plan_progress`）。
4. **缺少命令参数**：例如 `soul-agent memory --type preference` 尚未实现。
5. **错误处理较简单**：初始化失败和运行失败只输出错误文本，未来可按错误类型给出建议。
