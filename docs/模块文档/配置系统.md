# 配置系统详解

## 概述

Soul-agent 使用分层配置系统，支持 YAML 文件、环境变量和 `.env` 文件三种配置方式。配置加载遵循明确的优先级顺序，并通过 Pydantic 模型进行类型验证。

---

## 配置加载流程 (`settings.py` — `load_config`)

```
┌─────────────────────────────────────────────┐
│             load_config() 流程               │
│                                             │
│  ① 加载 .env 文件 (python-dotenv)           │
│       ↓                                     │
│  ② 以 DEFAULT_CONFIG 为基础 (defaults.py)    │
│       ↓                                     │
│  ③ 加载 YAML 文件并深度合并 (_deep_merge)    │
│       ↓                                     │
│  ④ 解析环境变量引用 (_resolve_env_vars)      │
│       ↓                                     │
│  ⑤ 直接环境变量覆盖                          │
│     OPENAI_API_KEY → llm.api_key            │
│     OPENAI_BASE_URL → llm.base_url          │
│     SOUL_AGENT_MODEL → llm.model            │
│       ↓                                     │
│  ⑥ Pydantic AppConfig 模型验证              │
│       ↓                                     │
│  ⑦ 返回 AppConfig 实例                      │
└─────────────────────────────────────────────┘
```

**优先级（从低到高）：**

```
DEFAULT_CONFIG (defaults.py)  ←  最低优先级
       ↑
YAML 配置文件
       ↑
${ENV_VAR} 环境变量引用
       ↑
直接环境变量覆盖              ←  最高优先级
```

### 关键内部函数

#### `_deep_merge(base, override)`

递归深度合并两个字典。当 `base` 和 `override` 中同一键的值都是字典时，递归合并；否则 `override` 的值直接覆盖 `base`。

```python
def _deep_merge(base: dict, override: dict) -> dict:
    """递归合并字典，override 中的非字典值直接覆盖 base"""
    result = base.copy()
    for key, value in override.items():
        if key in result and isinstance(result[key], dict) and isinstance(value, dict):
            result[key] = _deep_merge(result[key], value)
        else:
            result[key] = value
    return result
```

**示例：**

```python
base = {
    "llm": {"provider": "openai", "model": "gpt-4o-mini", "temperature": 0.7},
    "agent": {"max_iterations": 10}
}
override = {
    "llm": {"model": "gpt-4o", "temperature": 0.3}
}
# 合并结果：
{
    "llm": {"provider": "openai", "model": "gpt-4o", "temperature": 0.3},
    "agent": {"max_iterations": 10}
}
```

## 完整配置结构

### 顶层 — `AppConfig`

```python
class AppConfig(BaseModel):
    llm: LLMConfig
    agent: AgentConfig
    memory: MemoryConfig
    tools: ToolsConfig
    ui: UIConfig
```

---

### `LLMConfig` — 语言模型配置

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `provider` | `str` | `"openai"` | 模型提供商，支持 `"openai"` 或 `"local"` |
| `model` | `str` | `"gpt-4o-mini"` | 模型名称 |
| `api_key` | `str \| None` | `None` | API 密钥 |
| `base_url` | `str \| None` | `None` | 自定义 API 端点 URL |
| `temperature` | `float` | `0.7` | 生成温度，控制输出随机性（0.0-2.0） |
| `max_tokens` | `int` | `4096` | 最大输出 token 数 |

```yaml
llm:
  provider: "openai"
  model: "gpt-4o-mini"
  api_key: null           # 建议通过环境变量设置
  base_url: null           # 使用默认 OpenAI 端点
  temperature: 0.7
  max_tokens: 4096
```

---

### `AgentConfig` — Agent 行为配置

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `max_iterations` | `int` | `10` | 单次查询中 Agent 与工具交互的最大轮数 |
| `system_prompt_path` | `str \| None` | `None` | 自定义系统提示词文件路径，为 `None` 时使用内置提示词 |

```yaml
agent:
  max_iterations: 10
  system_prompt_path: null  # 或指定路径如 "./prompts/my_prompt.txt"
```

**`max_iterations` 说明：**

每次用户输入后，Agent 进入循环：调用 LLM → 执行工具 → 将结果返回 LLM → 再次调用 LLM... 这个循环的最大次数由 `max_iterations` 控制。设为 10 意味着 Agent 最多可以进行 10 轮工具调用。

---

### `MemoryConfig` — 记忆系统配置

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `enabled` | `bool` | `True` | 是否启用记忆系统 |
| `db_path` | `str` | `"./data/memory.db"` | SQLite 数据库文件路径 |
| `vector_db_path` | `str` | `"./data/chroma"` | ChromaDB 向量数据库存储路径 |
| `max_memories_per_query` | `int` | `5` | 每次检索返回的最大记忆条数 |
| `importance_threshold` | `float` | `0.3` | 最低重要性阈值，低于此值的记忆不会被存储 |
| `embedding_model` | `str` | `"text-embedding-3-small"` | 向量嵌入模型名称 |

```yaml
memory:
  enabled: true
  db_path: "./data/memory.db"
  vector_db_path: "./data/chroma"
  max_memories_per_query: 5
  importance_threshold: 0.3
  embedding_model: "text-embedding-3-small"
```

**字段详解：**

- **`enabled`**：设为 `false` 可完全禁用记忆系统，Agent 将不会存储或检索任何历史记忆
- **`db_path`**：SQLite 数据库用于存储记忆的结构化元数据
- **`vector_db_path`**：ChromaDB 用于存储记忆的向量表示，支持语义相似性检索
- **`max_memories_per_query`**：每次用户查询时，最多从记忆库中检索多少条相关记忆注入上下文
- **`importance_threshold`**：重要性评分在 0.0 到 1.0 之间，低于阈值的记忆会被丢弃不存储
- **`embedding_model`**：用于将文本转换为向量的模型，需与 LLM 提供商兼容

---

### `ToolsConfig` — 工具系统配置

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `enabled` | `list[str]` | （见下方） | 启用的工具名称列表 |
| `shell` | `ShellConfig` | — | Shell 工具专属配置 |

#### `ShellConfig` — Shell 工具配置

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `timeout` | `int` | `30` | 命令执行超时时间（秒） |
| `blocked_commands` | `list[str]` | （见下方） | 被阻止的危险命令列表 |

```yaml
tools:
  enabled:
    - read_file
    - write_file
    - list_directory
    - run_command
    - web_request
    - search_files
  shell:
    timeout: 30
    blocked_commands:
      - "rm -rf /"
      - "rm -rf ~"
      - "format"
      - "shutdown"
      - "reboot"
      - "mkfs"
      - ":(){:|:&};:"
```

**`enabled` 列表是白名单机制：** 只有列出的工具会被注册到工具注册表中。未列出的工具即使代码存在也完全不可用。移除某个工具名即可禁用该工具。

**`blocked_commands` 的检查方式：** 使用字符串包含匹配。如果用户命令中包含黑名单中的任意一个字符串，则拒绝执行。

---

### `UIConfig` — 界面配置

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `theme` | `str` | `"monokai"` | 终端主题 |
| `stream` | `bool` | `True` | 是否启用流式输出 |
| `show_thinking` | `bool` | `False` | 是否显示 LLM 的思考过程 |
| `language` | `str` | `"zh"` | 界面语言 |

```yaml
ui:
  theme: "monokai"
  stream: true
  show_thinking: false
  language: "zh"
```

**字段详解：**

- **`theme`**：控制终端输出的语法高亮和颜色主题
- **`stream`**：启用后 LLM 的响应会逐 token 输出，提供更好的交互体验；禁用后等待完整响应再显示
- **`show_thinking`**：启用后会显示 LLM 的中间推理过程（如果模型支持）
- **`language`**：界面文本的语言，`"zh"` 为中文

## 环境变量

### 直接覆盖变量

以下环境变量会在配置加载的最后阶段直接覆盖对应的配置字段，优先级最高：

| 环境变量 | 覆盖的配置字段 | 说明 |
|----------|---------------|------|
| `OPENAI_API_KEY` | `llm.api_key` | API 密钥 |
| `OPENAI_BASE_URL` | `llm.base_url` | API 端点 |
| `SOUL_AGENT_MODEL` | `llm.model` | 模型名称 |

```python
# settings.py 中的覆盖逻辑
if os.environ.get("OPENAI_API_KEY"):
    config["llm"]["api_key"] = os.environ["OPENAI_API_KEY"]
if os.environ.get("OPENAI_BASE_URL"):
    config["llm"]["base_url"] = os.environ["OPENAI_BASE_URL"]
if os.environ.get("SOUL_AGENT_MODEL"):
    config["llm"]["model"] = os.environ["SOUL_AGENT_MODEL"]
```

### `${ENV_VAR}` 引用语法

在 YAML 配置文件中，任何字符串值都可以使用 `${ENV_VAR}` 语法引用环境变量：

```yaml
llm:
  api_key: "${OPENAI_API_KEY}"
  base_url: "${MY_API_BASE_URL}"

memory:
  db_path: "${DATA_DIR}/memory.db"
  vector_db_path: "${DATA_DIR}/chroma"
```

**注意：** `${ENV_VAR}` 引用会在配置加载的第④步被解析，而直接环境变量覆盖在第⑤步执行。因此，对于 `llm.api_key`、`llm.base_url` 和 `llm.model` 这三个字段，即使在 YAML 中通过 `${...}` 设置了值，也会被第⑤步的直接覆盖替换。

### `.env` 文件支持

Soul-agent 使用 `python-dotenv` 库在配置加载开始时（第①步）加载项目根目录下的 `.env` 文件。`.env` 文件中定义的变量会被加载到 `os.environ` 中，从而可以被后续的环境变量引用和覆盖机制使用。

```bash
# .env 文件示例
OPENAI_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
OPENAI_BASE_URL=https://api.openai.com/v1
SOUL_AGENT_MODEL=gpt-4o
DATA_DIR=./data
```

**`.env` 文件的优先级：** `python-dotenv` 默认不会覆盖已存在的环境变量。即如果系统中已经设置了 `OPENAI_API_KEY`，`.env` 文件中的同名变量不会生效。

## 各模型提供商配置指南

### 1. OpenAI（默认）

最简单的配置，只需设置 API 密钥：

```yaml
llm:
  provider: "openai"
  model: "gpt-4o-mini"   # 或 gpt-4o, gpt-4-turbo 等
  api_key: "${OPENAI_API_KEY}"
  # base_url 无需设置，使用默认的 OpenAI 端点
```

**或通过环境变量：**

```bash
export OPENAI_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
# 无需其他配置
```

### 2. DeepSeek

将 `base_url` 指向 DeepSeek 的 API 端点：

```yaml
llm:
  provider: "openai"          # DeepSeek 兼容 OpenAI 协议
  model: "deepseek-chat"      # 或 deepseek-coder
  api_key: "${DEEPSEEK_API_KEY}"
  base_url: "https://api.deepseek.com/v1"
```

**或通过环境变量：**

```bash
export OPENAI_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
export OPENAI_BASE_URL=https://api.deepseek.com/v1
export SOUL_AGENT_MODEL=deepseek-chat
```

### 3. Ollama（本地模型）

使用本地运行的 Ollama 模型，无需 API 密钥：

```yaml
llm:
  provider: "local"           # 使用 local 提供商
  model: "qwen2.5:14b"       # Ollama 中已拉取的模型
  # api_key: 不需要
  # base_url: 自动使用 localhost:11434/v1
  temperature: 0.7
  max_tokens: 4096
```

**说明：** 当 `provider` 设为 `"local"` 时，系统会自动将 `base_url` 设为 `http://localhost:11434/v1`（Ollama 默认的 OpenAI 兼容端点），无需手动配置。

**确保 Ollama 服务正在运行：**

```bash
# 启动 Ollama 服务
ollama serve

# 拉取模型（如果尚未拉取）
ollama pull qwen2.5:14b
```

### 4. 任意 OpenAI 兼容 API

任何兼容 OpenAI API 协议的服务都可以接入：

```yaml
llm:
  provider: "openai"
  model: "your-model-name"
  api_key: "${YOUR_API_KEY}"
  base_url: "https://your-api-endpoint.com/v1"
```

**常见兼容服务示例：**

| 服务 | base_url | 说明 |
|------|----------|------|
| Azure OpenAI | `https://{resource}.openai.azure.com/openai/deployments/{deployment}` | 需要额外的 API 版本参数 |
| 智谱 AI | `https://open.bigmodel.cn/api/paas/v4` | 使用 GLM 系列模型 |
| 月之暗面 (Kimi) | `https://api.moonshot.cn/v1` | 使用 moonshot 系列模型 |
| 硅基流动 | `https://api.siliconflow.cn/v1` | 聚合多种开源模型 |
| vLLM | `http://localhost:8000/v1` | 本地部署的 vLLM 服务 |

## Pydantic 验证

配置加载的最后一步是通过 Pydantic 的 `AppConfig` 模型进行验证。Pydantic 会：

1. **类型检查**：确保每个字段的值类型正确（如 `temperature` 必须是 `float`）
2. **默认值填充**：未提供的可选字段会使用默认值
3. **值约束验证**：检查值是否在有效范围内

如果验证失败，会抛出 `ValidationError` 异常，明确指出哪些字段有问题。

```python
# 验证示例
try:
    config = AppConfig(**config_dict)
except ValidationError as e:
    print(f"配置验证失败: {e}")
```

## 常见问题

### Q: YAML 文件中的值和环境变量冲突时，以哪个为准？

**环境变量优先。** 对于 `llm.api_key`、`llm.base_url` 和 `llm.model` 这三个字段，环境变量（`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`SOUL_AGENT_MODEL`）的值会覆盖 YAML 文件中的设置。这是在配置加载的第⑤步完成的，晚于 YAML 合并（第③步）。

### Q: 如何完全禁用记忆系统？

```yaml
memory:
  enabled: false
```

设为 `false` 后，Agent 不会存储或检索任何记忆。

### Q: 如何只启用文件操作工具，禁用网络和命令执行？

```yaml
tools:
  enabled:
    - read_file
    - write_file
    - list_directory
    - search_files
```

只需在 `enabled` 列表中列出允许的工具。`run_command` 和 `web_request` 未列出则不会被注册。

### Q: `.env` 文件放在哪里？

放在项目根目录下（与 `pyproject.toml` 同级）。`python-dotenv` 会在 `load_config()` 的第一步加载它。

### Q: 如何查看当前生效的配置？

当前没有内置的配置查看命令。可以在代码中打印 `AppConfig` 对象来检查：

```python
from src.config.settings import load_config

config = load_config()
print(config.model_dump())  # Pydantic v2
```
