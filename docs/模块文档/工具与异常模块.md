# 工具与异常模块

本文档描述 `soul_agent/utils/` 模块的内部结构。该模块提供跨模块复用的基础能力：日志配置和异常类型定义。

---

## 1. 模块组成

```
soul_agent/utils/
├── __init__.py        # 自定义异常类定义
├── exceptions.py      # 异常类重新导出
└── logger.py          # 日志配置与全局 logger
```

| 文件 | 主要对象 | 职责 |
|------|----------|------|
| `logger.py` | `setup_logger()`, `logger` | 创建标准 logging.Logger，支持控制台和文件输出 |
| `__init__.py` | `SoulAgentError` 等异常类 | 定义项目异常层级 |
| `exceptions.py` | `__all__` 导出 | 兼容从 `soul_agent.utils.exceptions` 导入异常 |

---

## 2. 日志系统

日志系统位于 `logger.py`。

### 2.1 setup_logger 函数

```python
def setup_logger(
    name: str = "soul_agent",
    level: str = "INFO",
    log_file: str | None = None,
) -> logging.Logger:
```

参数说明：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `name` | `"soul_agent"` | logger 名称 |
| `level` | `"INFO"` | logger 级别 |
| `log_file` | `None` | 可选日志文件路径 |

返回值：标准库 `logging.Logger` 对象。

### 2.2 日志级别设置

```python
logger = logging.getLogger(name)
logger.setLevel(getattr(logging, level.upper(), logging.INFO))
```

如果传入未知 level，会回退到 `logging.INFO`。

### 2.3 Handler 去重

```python
if not logger.handlers:
    ...
```

只有当前 logger 没有 handler 时才添加，避免模块重复导入导致日志重复输出。

### 2.4 日志格式

```python
formatter = logging.Formatter(
    "[%(asctime)s] %(levelname)s %(name)s: %(message)s",
    datefmt="%Y-%m-%d %H:%M:%S",
)
```

输出示例：

```text
[2025-06-02 03:00:00] WARNING soul_agent: Memory extraction failed: ...
```

### 2.5 控制台输出

```python
console_handler = logging.StreamHandler(sys.stderr)
console_handler.setLevel(logging.WARNING)
```

控制台 handler 输出到 `stderr`，并且只显示 `WARNING` 及以上级别。这样普通 INFO/DEBUG 不会污染用户正常交互界面。

### 2.6 文件输出

如果传入 `log_file`：

```python
log_path = Path(log_file)
log_path.parent.mkdir(parents=True, exist_ok=True)
file_handler = logging.FileHandler(log_file, encoding="utf-8")
```

会自动创建日志目录，并把完整日志写入文件。

### 2.7 全局 logger

```python
logger = setup_logger()
```

各模块直接导入使用：

```python
from soul_agent.utils.logger import logger

logger.warning("记忆检索失败")
logger.error("LLM调用失败")
```

## 3. 异常体系

异常类定义在 `utils/__init__.py`。

### 3.1 异常层级

```
Exception
└── SoulAgentError
    ├── ConfigError
    ├── LLMError
    ├── ToolError
    └── MemoryError
```

### 3.2 基础异常

```python
class SoulAgentError(Exception):
    """基础异常"""
    pass
```

所有项目自定义异常都应继承自 `SoulAgentError`，便于上层统一捕获。

### 3.3 具体异常类型

| 异常类 | 含义 | 适用场景 |
|--------|------|----------|
| `ConfigError` | 配置错误 | 配置文件格式错误、缺少必要字段、环境变量无效 |
| `LLMError` | LLM 调用错误 | API 调用失败、认证失败、模型响应解析失败 |
| `ToolError` | 工具执行错误 | 工具参数错误、执行失败、安全拦截 |
| `MemoryError` | 记忆系统错误 | SQLite/ChromaDB 异常、记忆写入/检索失败 |

当前代码中大部分模块采用日志 + 原异常抛出/返回错误结果的方式，自定义异常体系为后续更精细的错误处理预留。

### 3.4 exceptions.py 的作用

`exceptions.py` 重新导出异常类：

```python
from soul_agent.utils import SoulAgentError, ConfigError, LLMError, ToolError, MemoryError

__all__ = ["SoulAgentError", "ConfigError", "LLMError", "ToolError", "MemoryError"]
```

这样既支持：

```python
from soul_agent.utils import ToolError
```

也支持：

```python
from soul_agent.utils.exceptions import ToolError
```

## 4. 在各模块中的使用

### 4.1 Core 模块

Agent 在记忆检索、记忆更新、Agent 运行异常时记录日志：

```python
try:
    relevant_memories = await self.memory.retrieve(user_input)
except Exception as e:
    logger.warning(f"记忆检索失败: {e}")
```

### 4.2 LLM 模块

LLMClient 在 provider 调用失败时记录错误并重新抛出：

```python
try:
    return await self.provider.chat(...)
except Exception as e:
    logger.error(f"LLM调用失败: {e}")
    raise
```

### 4.3 Memory 模块

记忆系统在 ChromaDB 不可用、向量检索失败、记忆提取失败等情况下记录日志，并尽量降级运行：

```python
logger.warning("ChromaDB not installed, falling back to keyword search only")
logger.warning(f"Vector search failed: {e}, falling back to keyword search")
logger.warning(f"Memory extraction failed: {e}")
```

### 4.4 Tools 模块

ToolExecutor 捕获工具执行异常，将异常转成 `ToolResult` 风格的错误消息：

```python
except Exception as e:
    logger.error(f"工具执行失败 {name}: {e}")
    result = ToolResult(success=False, output="", error=str(e))
```

## 5. 设计原则

### 5.1 日志不干扰用户输出

默认控制台只打印 Warning 以上级别，避免调试日志影响终端助手正常回复。

### 5.2 可选文件日志

`setup_logger(log_file=...)` 预留了文件日志能力，后续可以在配置系统中加入日志路径。

### 5.3 异常类型集中定义

所有项目级异常放在 `utils` 中，避免各模块重复定义类似异常。

### 5.4 模块容错优先

当前实现倾向于优雅降级：

- ChromaDB 不可用 → 关键词搜索
- 摘要 LLM 失败 → 简单摘要
- 记忆提取失败 → 跳过本轮记忆写入
- 工具执行失败 → 返回工具错误消息给 LLM

这种策略提升了终端 Agent 的连续可用性。

## 6. 后续可改进点

1. **日志配置接入 YAML**：支持配置日志级别、日志文件路径、是否输出 debug。
2. **异常使用统一化**：各模块用自定义异常包装底层错误。
3. **结构化日志**：输出 JSON 日志，便于后续分析和排障。
4. **按模块 logger**：使用 `logging.getLogger(__name__)` 区分模块来源。
5. **错误码体系**：为 CLI/UI 展示更友好的错误提示。
