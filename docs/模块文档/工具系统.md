# 工具系统详解

## 概述

Soul-agent 的工具系统为 LLM 提供了与外部世界交互的能力。通过工具，Agent 可以读写文件、执行命令、发起网络请求和搜索文件内容。整个系统基于抽象基类设计，支持注册、发现和批量执行，并内置了多层安全防护机制。

---

## 架构总览

```
┌─────────────────────────────────────────────────┐
│                   Agent (agent.py)               │
│  run() 循环：LLM 调用 → 解析 tool_calls → 执行  │
```

## 核心组件

### Tool — 抽象基类 (`base.py`)

所有工具必须继承 `Tool` 抽象基类，并实现以下属性和方法：

| 成员 | 类型 | 说明 |
|------|------|------|
| `name` | `str` | 工具的唯一标识名称 |
| `description` | `str` | 工具的功能描述，会作为 function calling 的描述传给 LLM |
| `parameters` | `dict` | JSON Schema 格式的参数定义 |
| `execute(**kwargs)` | 抽象方法 | 工具的执行逻辑，返回 `ToolResult` |
| `to_schema()` | 方法 | 生成 OpenAI function calling 格式的 schema |

```python
from abc import ABC, abstractmethod

class Tool(ABC):
    name: str
    description: str
    parameters: dict  # JSON Schema

    @abstractmethod
    async def execute(self, **kwargs) -> ToolResult:
        """执行工具逻辑"""
        ...

    def to_schema(self) -> dict:
        """生成 OpenAI function calling 格式"""
        return {
            "type": "function",
            "function": {
                "name": self.name,
                "description": self.description,
                "parameters": self.parameters
            }
        }
```

### ToolResult — 执行结果 (`base.py`)

`ToolResult` 是一个数据类，封装了工具执行的返回信息：

| 字段 | 类型 | 说明 |
|------|------|------|
| `success` | `bool` | 执行是否成功 |
| `output` | `str` | 工具输出内容 |
| `error` | `str \| None` | 错误信息，成功时为 `None` |

```python
@dataclass
class ToolResult:
    success: bool
    output: str
    error: str | None = None
```

### ToolRegistry — 工具注册表 (`registry.py`)

基于字典的工具注册与发现中心：

| 方法/属性 | 说明 |
|-----------|------|
| `register(tool)` | 注册一个工具实例，以 `tool.name` 为键存入字典 |
| `get(name)` | 根据名称获取工具实例 |
| `schemas` | 属性，返回所有已注册工具的 schema 列表（用于传递给 LLM） |
| `names` | 属性，返回所有已注册工具的名称列表 |
| `get_descriptions()` | 返回工具的描述信息，用于嵌入系统提示词 |

```python
class ToolRegistry:
    def __init__(self):
        self._tools: dict[str, Tool] = {}

    def register(self, tool: Tool):
        self._tools[tool.name] = tool

    def get(self, name: str) -> Tool | None:
        return self._tools.get(name)

    @property
    def schemas(self) -> list[dict]:
        return [tool.to_schema() for tool in self._tools.values()]

    @property
    def names(self) -> list[str]:
        return list(self._tools.keys())

    def get_descriptions(self) -> str:
        # 返回格式化的工具描述，用于系统提示词
        ...
```

### ToolExecutor — 工具执行器 (`executor.py`)

负责将 LLM 返回的 `tool_calls` 转化为实际的工具调用，并封装返回消息：

| 方法 | 说明 |
|------|------|
| `execute(tool_call)` | 执行单个工具调用，返回 `tool` 角色的消息字典 |
| `execute_batch(tool_calls)` | 批量执行多个工具调用 |

`execute` 接收 LLM 返回的 `tool_call` 字典，从中解析出工具名称和参数，调用对应工具的 `execute` 方法，最终返回一个符合 OpenAI 消息格式的 `tool` 角色消息：

```python
# execute 返回的消息格式
{
    "role": "tool",
    "tool_call_id": "call_abc123",
    "content": "文件内容..."  # ToolResult.output 或错误信息
}
```

### 内置工具注册 (`builtin/__init__.py`)

`register_builtin_tools(registry, config)` 函数根据配置中的 `config.tools.enabled` 列表，有选择性地注册内置工具：

```python
def register_builtin_tools(registry: ToolRegistry, config: AppConfig):
    """根据配置注册启用的内置工具"""
    # 只注册 config.tools.enabled 列表中包含的工具
    # 例如 enabled: ["read_file", "write_file", "run_command"]
    # 则只注册这三个工具，其余不注册
```

## 六个内置工具

### 1. ReadFileTool — 读取文件 (`file_ops.py`)

| 属性 | 值 |
|------|------|
| **name** | `"read_file"` |
| **功能** | 读取指定路径的文件内容 |

**参数：**

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `path` | `string` | 是 | — | 文件路径 |
| `encoding` | `string` | 否 | `"utf-8"` | 文件编码 |

**安全限制：**

- `MAX_READ_SIZE = 100KB`（102400 字节）— 防止读取超大文件导致内存溢出
- 检查文件是否存在（`Path.exists()`）
- 检查路径是否为文件（`Path.is_file()`），拒绝读取目录

**执行流程：**

```
1. 验证 path 参数存在
2. 检查文件是否存在 → 不存在返回错误
3. 检查是否为文件 → 不是文件返回错误
4. 检查文件大小 → 超过 100KB 返回错误
5. 以指定编码读取文件内容
6. 返回 ToolResult(success=True, output=文件内容)
```

**返回示例：**

```
成功：ToolResult(success=True, output="文件实际内容...", error=None)
失败：ToolResult(success=False, output="", error="文件不存在: /path/to/file")
```

### 2. WriteFileTool — 写入文件 (`file_ops.py`)

| 属性 | 值 |
|------|------|
| **name** | `"write_file"` |
| **功能** | 将内容写入指定路径的文件 |

**参数：**

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `path` | `string` | 是 | — | 文件路径 |
| `content` | `string` | 是 | — | 要写入的内容 |
| `encoding` | `string` | 否 | `"utf-8"` | 文件编码 |

**特性：**

- 自动创建父目录：使用 `Path.mkdir(parents=True, exist_ok=True)` 确保目标路径存在
- 覆盖写入：如果文件已存在，内容会被完全覆盖

**执行流程：**

```
1. 解析 path，创建 Path 对象
2. 调用 path.parent.mkdir(parents=True, exist_ok=True) 创建父目录
3. 以指定编码写入 content
4. 返回 ToolResult(success=True, output="文件已写入: /path/to/file")
```

### 3. ListDirectoryTool — 列出目录内容 (`file_ops.py`)

| 属性 | 值 |
|------|------|
| **name** | `"list_directory"` |
| **功能** | 列出指定目录下的文件和子目录 |

**参数：**

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `path` | `string` | 是 | — | 目录路径 |
| `recursive` | `boolean` | 否 | `false` | 是否递归列出子目录内容 |

**实现细节：**

- 非递归模式：使用 `Path.iterdir()` 列出直接子项
- 递归模式：使用 `Path.rglob("*")` 递归遍历所有后代项
- 输出前缀：目录标记为 `[目录]`，文件标记为 `[文件]`

**输出格式示例：**

```
[目录] src
[目录] tests
[文件] README.md
[文件] pyproject.toml
[目录] src/core
[文件] src/core/agent.py
```

### 4. RunCommandTool — 执行Shell命令 (`shell.py`)

| 属性 | 值 |
|------|------|
| **name** | `"run_command"` |
| **功能** | 在系统 Shell 中执行命令 |

**参数：**

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `command` | `string` | 是 | — | 要执行的 Shell 命令 |
| `timeout` | `integer` | 否 | 配置值 | 命令超时时间（秒） |

**初始化：**

```python
def __init__(self, shell_config):
    # 从配置中获取超时时间和阻止命令列表
    self.timeout = shell_config.timeout         # 默认 30 秒
    self.blocked_commands = shell_config.blocked_commands  # 危险命令列表
```

**安全机制：**

| 机制 | 实现方式 | 说明 |
|------|----------|------|
| 命令黑名单 | 字符串包含检查（`in`） | 遍历 `blocked_commands` 列表，若命令中包含任一黑名单字符串则拒绝执行 |
| 执行超时 | `asyncio.wait_for(timeout)` | 超时后杀掉子进程 |
| 输出截断 | `MAX_OUTPUT_LENGTH = 10000` | 限制输出字符数，防止超长输出占满上下文 |
| 异步执行 | `asyncio.create_subprocess_shell` | 异步创建子进程，不阻塞主线程 |

**执行流程：**

```
1. 检查命令是否在 blocked_commands 黑名单中（字符串包含匹配）
   → 匹配则返回错误："命令被禁止"
2. 使用 asyncio.create_subprocess_shell 创建子进程
3. 使用 asyncio.wait_for 设置超时等待
   → 超时则 kill 进程，返回超时错误
4. 收集 stdout 和 stderr
5. 截断输出至 MAX_OUTPUT_LENGTH (10000 字符)
6. 返回结果（包含返回码、stdout、stderr）
```

**命令黑名单检查的工作方式：**

```python
# 假设 blocked_commands = ["rm -rf", "format", "shutdown"]
# 检查方式是字符串包含（string contains）
for blocked in self.blocked_commands:
    if blocked in command:
        # 拒绝执行
        return ToolResult(success=False, output="", error=f"命令被禁止: {blocked}")
```

## Agent 如何使用工具（`agent.py`）

Agent 的 `run()` 方法是核心循环，它将工具系统与 LLM 衔接起来：

```
用户输入
    │
    ▼
┌──────────────────────────────────────────────┐
│  Agent.run() 循环                             │
│                                              │
│  1. 将 tool_registry.schemas 传给 LLM        │
│  2. 调用 LLM 获取响应                         │
│  3. 检查响应中是否包含 tool_calls              │
│     ├─ 否 → 返回文本响应给用户                 │
│     └─ 是 → 继续步骤 4                        │
│  4. 构建包含 tool_calls 的 assistant 消息      │
│     追加到对话历史                             │
│  5. 通过 ToolExecutor 执行工具调用             │
│  6. 将工具返回的 tool 角色消息追加到对话历史     │
│  7. 回到步骤 2（再次调用 LLM）                 │
│                                              │
│  最大迭代次数: config.agent.max_iterations     │
│  (默认 10 次)                                 │
└──────────────────────────────────────────────┘
```

**详细流程：**

```python
async def run(self, user_input: str):
    # 将用户输入加入对话历史
    self.messages.append({"role": "user", "content": user_input})

    for i in range(self.config.agent.max_iterations):
        # 调用 LLM，传入工具 schemas
        response = await self.llm.chat(
            messages=self.messages,
            tools=self.tool_registry.schemas  # 所有已注册工具的 schema
        )

        message = response.choices[0].message

        if not message.tool_calls:
            # LLM 没有调用工具，直接返回文本
            return message.content

        # LLM 请求调用工具
        # 构建包含 tool_calls 的 assistant 消息并追加
        self.messages.append({
            "role": "assistant",
            "content": message.content,
            "tool_calls": message.tool_calls
        })

        # 执行所有工具调用
        tool_results = await self.executor.execute_batch(message.tool_calls)

        # 将工具结果追加到对话历史
        self.messages.extend(tool_results)

        # 循环继续，LLM 将看到工具结果并决定下一步
```

**迭代控制：**

`max_iterations`（默认 10）限制了单次用户查询中 Agent 与工具交互的最大轮数。这防止了 Agent 陷入无限循环。当达到最大迭代次数时，Agent 会强制返回当前结果。

## 安全防护体系

Soul-agent 的工具系统内置了多层安全机制：

| 安全层 | 位置 | 措施 | 详情 |
|--------|------|------|------|
| **工具白名单** | 配置文件 | `config.tools.enabled` 列表 | 只有在列表中的工具才会被注册，未列出的工具完全不可用 |
| **命令黑名单** | `shell.py` | `blocked_commands` 列表 | 字符串包含检查，阻止危险命令执行 |
| **Shell 超时** | `shell.py` | 默认 30 秒超时 | 防止长时间运行的命令占用资源，超时后杀死进程 |
| **文件大小限制** | `file_ops.py` | `MAX_READ_SIZE = 100KB` | 防止读取超大文件导致内存问题 |
| **输出截断** | `shell.py` / `web.py` | `MAX_OUTPUT_LENGTH = 10000` 字符 | 防止超长输出填满 LLM 上下文窗口 |
| **搜索结果限制** | `search.py` | `MAX_RESULTS = 100` | 限制搜索结果数量 |
| **迭代次数限制** | `agent.py` | `max_iterations` 默认 10 | 防止无限工具调用循环 |

**安全配置示例（YAML）：**

```yaml
tools:
  enabled:
    - read_file
    - write_file
    - list_directory
    - run_command
    - search_files
    # 注意：未列出 web_request，该工具将不可用
  shell:
    timeout: 30
    blocked_commands:
      - "rm -rf /"
      - "rm -rf ~"
      - "format"
      - "shutdown"
      - "reboot"
      - "mkfs"
      - ":(){:|:&};:"
```

## 工具 Schema 格式详解

`to_schema()` 方法生成符合 OpenAI function calling 规范的工具描述。以下以 `read_file` 工具为例展示完整的 schema 输出：

### `read_file` 的完整 Schema 示例

```json
{
    "type": "function",
    "function": {
        "name": "read_file",
        "description": "读取指定路径的文件内容",
        "parameters": {
            "type": "object",
            "properties": {
                "path": {
                    "type": "string",
                    "description": "要读取的文件路径"
                },
                "encoding": {
                    "type": "string",
                    "description": "文件编码",
                    "default": "utf-8"
                }
            },
            "required": ["path"]
        }
    }
}
```

### Schema 结构说明

```
{
    "type": "function",          ← 固定值，表示这是一个函数工具
    "function": {
        "name": "...",           ← Tool.name — 工具唯一标识
        "description": "...",    ← Tool.description — 功能描述
        "parameters": {          ← Tool.parameters — JSON Schema 格式
            "type": "object",
            "properties": {
                "参数名": {
                    "type": "参数类型",
                    "description": "参数描述",
                    ...
                }
            },
            "required": ["必填参数列表"]
        }
    }
}
```

## 自定义工具开发指南

如果需要添加新的工具，按照以下步骤操作：

### 第一步：继承 Tool 基类

```python
# src/tools/builtin/my_tool.py
from src.tools.base import Tool, ToolResult

class MyCustomTool(Tool):
    name = "my_tool"
    description = "我的自定义工具，用于执行某项操作"
    parameters = {
        "type": "object",
        "properties": {
            "input_data": {
                "type": "string",
                "description": "输入数据"
            },
            "option": {
                "type": "boolean",
                "description": "可选开关",
                "default": False
            }
        },
        "required": ["input_data"]
    }

    async def execute(self, **kwargs) -> ToolResult:
        input_data = kwargs.get("input_data")
        option = kwargs.get("option", False)

        try:
            # 执行自定义逻辑
            result = do_something(input_data, option)
            return ToolResult(success=True, output=result)
        except Exception as e:
            return ToolResult(success=False, output="", error=str(e))
```

### 第二步：在 `register_builtin_tools` 中注册

```python
# src/tools/builtin/__init__.py
from .my_tool import MyCustomTool

def register_builtin_tools(registry, config):
    # ... 现有工具注册 ...

    if "my_tool" in config.tools.enabled:
        registry.register(MyCustomTool())
```

### 第三步：在配置中启用

```yaml
tools:
  enabled:
    - read_file
    - write_file
    - my_tool  # 添加新工具
```

## 常见问题

### Q: 工具调用失败时 Agent 会怎么处理？

当工具返回 `ToolResult(success=False, ...)` 时，错误信息会作为 `tool` 角色的消息返回给 LLM。LLM 会看到错误内容，并可以：
- 尝试用不同参数重新调用工具
- 换用其他工具达成目标
- 向用户报告错误并解释原因

### Q: 为什么 Shell 的命令黑名单用字符串包含检查？

字符串包含检查（`blocked_cmd in command`）是一种简单但有效的防护。例如当 `"rm -rf /"` 在黑名单中时，命令 `"sudo rm -rf / --no-preserve-root"` 也会被拦截，因为它包含了 `"rm -rf /"`。这种方式虽不能防御所有绕过手段，但作为第一道防线已经足够。

### Q: MAX_OUTPUT_LENGTH 截断不会导致信息丢失吗？

会的。当输出超过 10000 字符时，多余部分会被截断。这是一个权衡——LLM 的上下文窗口有限，过长的工具输出会挤占其他重要信息。如果 Agent 需要处理大量输出，建议通过管道、过滤等方式在命令层面控制输出量。
