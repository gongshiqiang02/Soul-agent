# 迭代更新记录

## 2026-06-12 记忆系统：相关性过滤 + 去重机制

### 背景

记忆系统存在两个核心问题：
1. **存储了大量无关信息** — 工具输出、代码片段、命令结果等被 LLM 当作"值得记住的信息"存进了记忆
2. **记忆重复累积** — 没有任何去重机制，相同或近似的记忆被反复存储

### 改动内容

#### 1. 提取提示词优化（`memory/manager.py`）

- 替换 `EXTRACT_MEMORIES_PROMPT`，增加相关性过滤规则和判断标准
- 正面采用原则导向（"能否帮助未来更好地理解用户"），而非穷举清单
- 负面明确过滤：工具调用结果、代码片段、命令输出、临时任务信息

#### 2. SHA-256 精确去重（`memory/long_term.py`）

- `memories` 表新增 `content_hash` 列（TEXT UNIQUE）
- `store()` 方法写入前自动计算 `SHA-256(strip + lower)` 哈希，已存在则返回已有 ID
- 新增 `find_by_hash()` 方法
- 新增 `_migrate_add_content_hash()` 迁移方法，兼容旧数据库自动加列 + 填充哈希 + 建索引
- 修复：UNIQUE INDEX 创建从 `executescript` 移到迁移方法，解决旧数据库初始化报错

#### 3. 向量相似度近似去重（`memory/retriever.py`）

- 新增 `check_duplicate(content, threshold=0.80)` 方法
- 通过 ChromaDB 向量查询检测语义近似的已有记忆
- `MemoryManager.store()` 在写入前先调用此方法，命中则跳过存储
- ChromaDB 不可用时自动跳过，不报错

#### 4. 重要性阈值调整（`config/defaults.py` + `config/settings.py`）

- `importance_threshold` 从 0.3 提高到 0.5，过滤更多低价值记忆

#### 5. 历史数据清理工具（`memory/long_term.py`）

- 新增 `cleanup_duplicates()` 方法，清理已有数据库中的重复记忆（保留重要性最高的）

#### 6. 死代码清理（`llm/prompts.py`）

- 删除从未被引用的 `MEMORY_EXTRACTION_PROMPT`
